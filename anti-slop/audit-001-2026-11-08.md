# UI Audit 001

Date: 2026-11-08
Mode: AFTER
Scope: static source review of the shared app shell, login, dashboard, and global styles.

This is a code inspection only. The app was not launched, so visual breakpoints, browser contrast rendering, and click-through behavior still need runtime verification.

## Findings

### 1. HIGH - Login keyboard focus is hidden (R-32)

`src/components/auth/LoginView.jsx:314,333` applies `focus:outline-none` to the quick-login action and role shortcut buttons without a visible replacement focus indicator. Keyboard users can lose track of the active control.

### 2. HIGH - Header icon buttons are below the minimum touch size (R-03)

`src/components/layout/Header.jsx:123-129,293-299` gives the 16px menu and notification icons 8px padding, making those controls about 32px square. The antislop mobile rule requires a minimum 44px tap target.

### 3. HIGH - Small muted text does not meet the stated contrast target (R-25)

`src/components/dashboard/DashboardAnalytics.jsx:354` and `src/components/layout/Header.jsx:175` use 10px `text-slate-400` on light surfaces. Tailwind slate-400 (`#94a3b8`) on white is about 2.56:1, below the 4.5:1 requirement for normal text.

### 4. HIGH - Motion has no reduced-motion accommodation (R-39)

`src/index.css:90-104` defines a 26-second infinite Ken Burns animation, and multiple components use repeating `animate-pulse` effects, but no `prefers-reduced-motion` rule was found. People who request reduced motion still receive continuous animation.

### 5. LOW - Typography choices have no recorded design rationale (R-31)

`src/index.css:31-61` registers several display-font utilities alongside the body font, but no `DESIGN.md` or rationale was found to explain which roles each typeface serves. This makes later UI changes likely to add more inconsistent typography choices.
